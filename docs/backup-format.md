# 备份与恢复

设置 → 备份与恢复：开启自动备份后，设置保存、条目位置调整及引用的自定义图标/背景文件变化会创建备份点。静态文件的外部修改每 3 秒检查一次。内容没有变化时不重复创建备份。

自动备份最多保留 30 条，按创建时间清理最旧记录。点击「保存」后不参与自动清理；手动创建、导入及恢复前保护备份默认均为已保存状态。可重命名、导出、恢复或删除备份点。恢复前先创建当前状态的保护备份，配置写入成功后刷新界面、主题、快捷键及开机自启。

首次运行支持本功能的程序会在当前用户下关联 `.qdtbackup`。双击文件打开设置中的恢复页面，并导入到已保存列表；需要点击恢复才应用。已运行时通过当前用户专属命名管道转交文件。注册被系统限制时仍可通过设置页导入。没有复制应用程序本体或启动目标文件；目标路径原样保留。源图像已丢失时保留路径，界面使用既有默认图标/背景回退。

## 存储协议（格式 1）

`.qdtbackup` 是 ZIP，包含 `manifest.json`、`config.json`、`assets/<SHA256>.<扩展名>`。配置中的静态资源使用 `qdtasset:assets/...` 引用。相同资源去重；恢复到独立的 `RestoredAssets/<随机 ID>` 目录，不覆盖现有图像。

清单包含 `Format: LaunchPad.Backup`、`FormatVersion: 1`、`Version`、`CreatedUtc`。软件版本不作为拒绝导入的条件；没有清单但具有有效 `config.json` 的旧格式包也可读取。导入会保留原始包。读取最多接受 10,000 个条目、512 MB 解压内容；拒绝重复条目、不安全的静态资源路径、无效配置及缺失的包内引用。

备份存放于 `%AppData%/LaunchPad/Backups`。每个点有独立的 `.qdtbackup` 与 `.json` 元信息；保存标志与名称属于本机元信息，不改变导出包中的配置。

## 后续版本兼容约定

- 新增配置使用可选字段并提供默认值，保持现有字段名称与类型；不复用已有字段表达不兼容语义。
- 根配置、分类、条目及主题的未知字段通过 JSON 扩展数据原样保留。
- 未识别的 `kind` 条目暂不显示，保存时保留原始条目及顺序引用；将来支持该类型的版本可以再次读取。
- 新资源字段继续使用 `qdtasset:` 包内引用，新增类型应延续此协议；不以软件版本号阻止读取。
- 此兼容策略适用于包含本功能的版本；已发布、未实现备份读取的历史二进制无法由本次改动补充功能。

## 验证

`dotnet run --project Tests/BackupTests.csproj`：使用隔离临时目录，覆盖 30 条清理、保存保护、去重、静态资源往返、旧配置默认值、未知字段/类型保留、非法 ZIP 拒绝、重命名、删除、外部文件变化、禁用自动备份、进程间文件转交及浅色/深色设置页离屏渲染。测试不修改真实配置或注册文件关联。
